# Changelog

## [Unreleased]

- Fixes from the final review: `Insert` marshals rows addressably, so a pointer-receiver `MarshalJSON` (`big.Int`, nested too) applies; `IsRetryable` follows the call's own resend rule (a raw SQL error, or a pipe's bare 5xx, is not retryable although `APIError.Retryable` may be set); header names must be tokens and values pass `net/http`'s field-value rule (no control bytes but tab, no DEL), from `WithHeader`, `WithHeaderFunc`, per-call `Header`, `SubscribeOptions.Header` and `WithUserAgent`; `New` refuses a base URL that is a path (`/api/warehouse`) instead of reading its first segment as a host.
- `Subscribe` no longer reconnects forever on a frame it can't decode (not JSON, over the 32 MiB cap, or a schema frame that is malformed or repeats a column name). The first failure reconnects as before; if the same frame fails again at the same place, it is skipped, the resume point moves past it, and the new `SubscribeOptions.OnDrop` is called with the reason and the frame's id, never its payload. A server's `retry:` field is a floor under every reconnect wait.
- `RetryPolicy.AttemptTimeout` (default 0, off) gives each attempt its own deadline, linked to the caller's ctx. It covers a REST call from sending to the end of its body, and each stream connect up to the response headers; an established stream is not cut off. An attempt that hits it is retried after a backoff within `MaxAttempts`, under the transport-error rules: a raw SQL or pipe call is not resent once its request headers were written (decided with `httptrace`, not by the error type), and one that hit the limit while still connecting is. The caller's own cancel or deadline ends the call at once and is never retried. The final error names the attempt count and matches the new `ErrAttemptTimeout`, not `context.DeadlineExceeded`. A negative value is an error from `New`. Mirrors the JS SDK's `attemptTimeoutMs`.
- The `WithTokenSource` contract is documented: it runs before every attempt, every retry and every stream connect included, must be cheap, and caching or refreshing is the implementer's job. It was already the behaviour, and is now pinned by tests.
- Per-call headers: `Query.Header`, `PipeCall.Header` and `SQLCall.Header` (copies; they apply to `Scan`, `Fetch`, `Exec` and `Insert`) and `SubscribeOptions.Header`. `WithHeaderFunc` adds headers computed before every attempt and every stream connect, under the `WithTokenSource` contract; its error fails the attempt like a token source error (the first stream connect returns it, a stream that has been live retries it). Precedence, lowest to highest: `WithHeader`, `WithHeaderFunc`, the call's `Header`, then the SDK's own (Authorization, Content-Type, Accept, User-Agent). The shared conformance cases gain an optional `"call_headers"` map. Mirrors the JS SDK's per-call `headers`.
- A data frame that arrives before any schema frame on a connection is a protocol error, even when its row is empty: the stream reconnects from the last delivered event, as it does for a row whose length disagrees with the columns.
- `GroupBy` no longer adds its columns to the selection; it only fills `group_by`, as in the JS SDK. A caller who wants the key back selects it too: `Select("page").GroupBy("page")`. The server's handling of grouping keys is tracked in [Wave-RF/WaveHouse#295](https://github.com/Wave-RF/WaveHouse/issues/295). The shared conformance cases merge the Go-only and JS-only group-by cases into one.
- Admin calls take a per-call tenant: `ForTenant(id)`, a trailing `AdminOption` on `Tables`, `TableSchema`, `RefreshSchema`, `DLQStats`, `ReloadSettings`, `Pipes` and `PipeDefinition`, and `SQLCall.ForTenant(id)` for raw SQL (a copy; it applies to `Scan`, `Fetch` and `Exec`). It sends `?tenant=<id>`, because the `/v1/ops/*` routes ignore the `X-Tenant-ID` header, which stays the caller's through `WithHeader`; an unknown tenant is `ErrNotFound` and an empty id sends nothing. The shared conformance cases for the three `?tenant=` calls now run in both SDKs. Mirrors the JS SDK's `tenant` option.
- The SDK has no tenant handling of its own: sending `X-Tenant-ID` on a multi-tenant server is the caller's job, through `WithHeader("X-Tenant-ID", "acme")`. A header set that way, `X-Tenant-ID` included, is sent unchanged on every REST call and on the stream; the SDK owns only Authorization, Content-Type, Accept and User-Agent. The shared conformance cases gain an optional `"headers"` map (request headers set through the header hook).
- `New` accepts a base URL with no scheme: it gets `http://` for a loopback host (`localhost`, `127.0.0.0/8`, `::1`, `*.localhost`) and `https://` for any other, and an explicit scheme is never changed. It used to return an error. The JS SDK resolves the same inputs to the same base.
- The shared request-conformance cases gain an optional `"sdks"` list, and the Go replay skips cases that exclude Go. The JS SDK replays the same file.
- `Client.Subscribe` streams a table's rows over `GET /v1/stream`, read like `sql.Rows` (`Next`, `Event`, `Err`, `Close`) or as a channel (`Events`, closed when the subscription ends; use one or the other). It zips the server's `event: schema` column announcements with each positional row into an `Event` (`Row()` returns a `Row` with typed accessors, `Decode(dst)`, numbers as `json.Number`), reconnects with backoff and `Last-Event-ID`, stops on any non-retryable status or a 2xx that is not an event stream, and reports its connection state through `SubscribeOptions.OnState`. `Since` replays from a time and `ResumeID` from a checkpointed event.
- **Breaking:** the client core and admin calls are rewritten. `New(baseURL, opts...)` with `WithToken`, `WithTokenSource`, `WithOperatorKey`, `WithRetry`, `WithHTTPClient`, `WithHeader` and `WithUserAgent` replaces `NewClient(Config)`. Health, version, schema, DLQ, pipe-definition and settings-reload calls are methods on `Client`. Failures are `*APIError` (with the server's `code`, `retryable` and `X-Request-Id`), matched with `errors.Is` against `ErrNotFound` and the other sentinels; retries depend on whether resending is safe and honour `Retry-After`. JSON numbers decode as `json.Number`. Go 1.26 is now the minimum.
- **Breaking:** ingest, queries, pipes and raw SQL are rewritten onto the new core. `Client.From(table)` starts an immutable query builder (`Select`, `SelectAll`, `Where`, `OrderBy`, `GroupBy`, `Limit`, `TimeRange`, `Count`, `Sum`, `Avg`, `Min`, `Max`, `CountDistinct`, `Aggregate`) that ends in `Scan(ctx, &rows)` for structs or maps, or `Fetch(ctx)` for `[]Row`, where `Row` is a map type with typed accessors (`String`, `Int64`, `Uint64`, `Float64`, `Bool`, `Time`); builder misuse is an error from `Scan`/`Fetch`, not a panic, including an unknown `Op` or `Dir` (`"DESC"` is accepted), and an empty `In` list. `Select("*")` names a column called `*`, as in the JS SDK (`SelectAll` reads every readable column), `GroupBy` sends `group_by` and nothing more, so select the key too (`Select("page").GroupBy("page")`) to get it back (server behaviour tracked in [Wave-RF/WaveHouse#295](https://github.com/Wave-RF/WaveHouse/issues/295)), and an empty alias is `count`, `sum_<column>`, `avg_<column>`, `min_<column>`, `max_<column>` or `count_distinct_<column>`, while `Aggregate` with no alias sends none. `TimeRange(column, from, to time.Time)` sends RFC 3339 in UTC with nanoseconds and `Last(column, d)` the server's relative form. `Client.TableSchema` (not `Table`) reads one table's schema. `Query.Insert` takes a struct, map or slice on a bare `From(table)` (read state is an error) and always sends NDJSON, so every call returns the per-record `InsertResult`; rejected records also return an `*InsertError`, and `InsertNDJSON` sends a pre-encoded body. `Client.Pipe(name).Param(...).Scan(ctx, &rows)` runs a pipe (`Exec` for one that writes) and `Client.SQL(query)` has `Scan`, `Fetch` and `Exec`. UInt64 and Int64 stay exact. Removed because the server dropped them or never honoured them: the policy endpoints, pipe writers, `CacheTTL` (a no-op) and `not_like` (the server rejects it); the client-side default limit of 1000 is gone, so a query without `Limit` is capped by the server alone. Live queries and pagination return once the server supports them (Wave-RF/WaveHouse#951, Wave-RF/WaveHouse#452).
- Imported, with history, from the `go-sdk` branch of WaveHouse ([Wave-RF/WaveHouse#434](https://github.com/Wave-RF/WaveHouse/pull/434)). Not released yet; it is caught up with the server protocol as of this branch.
