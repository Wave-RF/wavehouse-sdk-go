# Changelog

## [Unreleased]

- `New` accepts a base URL with no scheme: it gets `http://` for a loopback host (`localhost`, `127.0.0.0/8`, `::1`, `*.localhost`) and `https://` for any other, and an explicit scheme is never changed. It used to return an error. The JS SDK resolves the same inputs to the same base.
- The shared request-conformance cases gain an optional `"sdks"` list, and the Go replay skips cases that exclude Go. The JS SDK replays the same file.
- `Client.Subscribe` streams a table's rows over `GET /v1/stream`, read like `sql.Rows` (`Next`, `Event`, `Err`, `Close`) or as a channel (`Events`, closed when the subscription ends; use one or the other). It zips the server's `event: schema` column announcements with each positional row into an `Event` (`Row()` returns a `Row` with typed accessors, `Decode(dst)`, numbers as `json.Number`), reconnects with backoff and `Last-Event-ID`, stops on 400/401/403/404, and reports its connection state through `SubscribeOptions.OnState`. `Since` replays from a time and `ResumeID` from a checkpointed event.
- **Breaking:** the client core and admin calls are rewritten. `New(baseURL, opts...)` with `WithToken`, `WithTokenSource`, `WithOperatorKey`, `WithTenant`, `WithRetry`, `WithHTTPClient`, `WithHeader` and `WithUserAgent` replaces `NewClient(Config)`; `Client.WithTenant` derives a client for another tenant. Health, version, schema, DLQ, pipe-definition and settings-reload calls are methods on `Client`. Failures are `*APIError` (with the server's `code`, `retryable` and `X-Request-Id`), matched with `errors.Is` against `ErrNotFound` and the other sentinels; retries depend on whether resending is safe and honour `Retry-After`. JSON numbers decode as `json.Number`. Go 1.26 is now the minimum.
- **Breaking:** ingest, queries, pipes and raw SQL are rewritten onto the new core. `Client.From(table)` starts an immutable query builder (`Select`, `SelectAll`, `Where`, `OrderBy`, `GroupBy`, `Limit`, `TimeRange`, `Count`, `Sum`, `Avg`, `Min`, `Max`, `CountDistinct`, `Aggregate`) that ends in `Scan(ctx, &rows)` for structs or maps, or `Fetch(ctx)` for `[]Row`, where `Row` is a map type with typed accessors (`String`, `Int64`, `Uint64`, `Float64`, `Bool`, `Time`); builder misuse is an error from `Scan`/`Fetch`, not a panic, including an unknown `Op` or `Dir` (`"DESC"` is accepted), and an empty `In` list. `Select("*")` names a column called `*`, as in the JS SDK (`SelectAll` reads every readable column), `GroupBy` columns are selected for you, and an empty alias is `count`, `sum_<column>`, `avg_<column>`, `min_<column>`, `max_<column>` or `count_distinct_<column>`, while `Aggregate` with no alias sends none. `TimeRange(column, from, to time.Time)` sends RFC 3339 in UTC with nanoseconds and `Last(column, d)` the server's relative form. `Client.TableSchema` (not `Table`) reads one table's schema. `Query.Insert` takes a struct, map or slice on a bare `From(table)` (read state is an error) and always sends NDJSON, so every call returns the per-record `InsertResult`; rejected records also return an `*InsertError`, and `InsertNDJSON` sends a pre-encoded body. `Client.Pipe(name).Param(...).Scan(ctx, &rows)` runs a pipe (`Exec` for one that writes) and `Client.SQL(query)` has `Scan`, `Fetch` and `Exec`. UInt64 and Int64 stay exact. Removed because the server dropped them or never honoured them: the policy endpoints, pipe writers, `CacheTTL` (a no-op) and `not_like` (the server rejects it); the client-side default limit of 1000 is gone, so a query without `Limit` is capped by the server alone. Live queries and pagination return once the server supports them (Wave-RF/WaveHouse#951, Wave-RF/WaveHouse#452).
- Imported, with history, from the `go-sdk` branch of WaveHouse ([Wave-RF/WaveHouse#434](https://github.com/Wave-RF/WaveHouse/pull/434)). Not released yet; the SDK still has to catch up with the current server protocol.
